<objective>
Fix the bug where organization owners cannot configure role permissions on the tenant-web permission management page. Root cause: `usePermissions` useQuery has no error handler, so API failures cause `permissions = []`, making `hasPermission('settings:view')` return false for the owner.
</objective>

<tasks>

<task type="auto">
  <name>Add error handling and owner role awareness to usePermissions hook</name>
  <files>tenant-web/src/hooks/use-permissions.ts</files>
  <action>
    Modify the useQuery call to add an onError handler that logs failures without crashing.

    Change:
    ```typescript
    const { data: response, isLoading } = useQuery({
      queryKey: ['my-permissions', targetOrgId],
      queryFn: () => (targetOrgId ? permissionsApi.getMyPermissions(targetOrgId) : null),
      enabled: !!targetOrgId,
      staleTime: 5 * 60 * 1000,
    });
    ```

    To:
    ```typescript
    const { data: response, isLoading, error } = useQuery({
      queryKey: ['my-permissions', targetOrgId],
      queryFn: () => (targetOrgId ? permissionsApi.getMyPermissions(targetOrgId) : null),
      enabled: !!targetOrgId,
      staleTime: 5 * 60 * 1000,
      onError: (err) => {
        console.error('[usePermissions] Failed to load permissions:', err);
      },
    });
    ```

    Also expose `error` in the return value so callers can react to it:
    ```typescript
    return {
      permissions,
      systemRoles,
      isSuperAdmin,
      isLoading,
      error,  // Add this
      hasPermission,
      hasAnyPermission,
      hasAllPermissions,
      hasSystemRole,
    };
    ```
  </action>
  <verify>pnpm type-check --filter tenant-web 2>&1 | tail -5</verify>
  <done>usePermissions hook has onError handler and exposes error state</done>
</task>
