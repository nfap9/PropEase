<objective>
重构 API 路由文件，实现「薄路由 + 厚控制器」(thin routes + fat controllers) 模式。将路由文件中的处理逻辑提取到独立的 controller 文件，路由文件只保留路由定义（5-10 行）。

Purpose: 提高代码可维护性，让路由定义和处理逻辑分离，便于测试和复用。
Output: 5 个路由文件变为薄路由，5 个对应的 controller 文件包含所有处理逻辑。
</objective>

6. 更新 apartments.ts 为薄路由:
```typescript
import { Router } from 'express';
import { requireConsoleAuth } from '../../middlewares/requireAuth.js';
import * as ctrl from './apartments.controller.js';

const router = Router();
router.use(requireConsoleAuth);

router.get('/', ctrl.list);
router.get('/:id', ctrl.get);
router.post('/', ctrl.create);
router.put('/:id', ctrl.update);
router.delete('/:id', ctrl.delete);
router.post('/bulk-delete', ctrl.bulkDelete);

// rooms sub-resource
router.get('/:id/rooms', ctrl.listRooms);
router.get('/:apartmentId/rooms/:roomId', ctrl.getRoom);
router.post('/:apartmentId/rooms', ctrl.createRoom);
router.put('/:apartmentId/rooms/:roomId', ctrl.updateRoom);
router.delete('/:apartmentId/rooms/:roomId', ctrl.deleteRoom);
router.post('/:id/rooms/batch', ctrl.batchCreateRooms);

// utility config
router.get('/:id/utility-config', ctrl.getUtilityConfig);
router.put('/:id/utility-config', ctrl.updateUtilityConfig);

export const apartmentsRouter = router;
```
