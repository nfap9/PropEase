## 二、索引优化（高优先级）

### 2.1 缺失索引分析

| 表名 | 字段 | 查询场景 | 影响程度 |
|-----|------|---------|---------|
| `leases` | `tenant_id` | 按租客查询租约 | 高 |
| `bills` | `lease_id` | 按租约查询账单 | 高 |
| `bills` | `(lease_id, bill_year, bill_month)` | 按租约+月份查询 | 高 |
| `utility_readings` | `room_id` | 按房间查询水电 | 高 |
| `tenants` | `organization_id` | 按组织查询租客 | 中 |
| `apartments` | `organization_id` | 按组织查询公寓 | 中 |
| `notifications` | `user_id` | 查询用户通知 | 中 |
| `notifications` | `(user_id, is_read)` | 查询未读通知 | 中 |
| `subscription_orders` | `organization_id` | 按组织查询订单 | 中 |
| `usage_quotas` | `user_id` | 查询用户配额 | 中 |
| `usage_quotas` | `(user_id, valid_from, valid_to)` | 查询有效配额 | 中 |

### 2.2 索引添加脚本

```sql
-- 租约表索引
CREATE INDEX idx_leases_tenant_id ON leases(tenant_id);
CREATE INDEX idx_leases_room_active ON leases(room_id, is_active);

-- 账单表索引
CREATE INDEX idx_bills_lease_id ON bills(lease_id);
CREATE INDEX idx_bills_lease_period ON bills(lease_id, bill_year, bill_month);

-- 水电读数表索引
CREATE INDEX idx_utility_readings_room_id ON utility_readings(room_id);

-- 租客表索引
CREATE INDEX idx_tenants_organization_id ON tenants(organization_id);

-- 公寓表索引
CREATE INDEX idx_apartments_organization_id ON apartments(organization_id);

-- 通知表索引
CREATE INDEX idx_notifications_user_id ON notifications(user_id);
CREATE INDEX idx_notifications_user_unread ON notifications(user_id, is_read);

-- 订阅订单表索引
CREATE INDEX idx_subscription_orders_organization_id ON subscription_orders(organization_id);

-- 配额表索引
CREATE INDEX idx_usage_quotas_user_id ON usage_quotas(user_id);
CREATE INDEX idx_usage_quotas_user_valid ON usage_quotas(user_id, valid_from, valid_to);
```

## 三、唯一约束优化（高优先级）

### 3.1 防止重复数据

| 表名 | 字段组合 | 原因 |
|-----|---------|------|
| `utility_readings` | `(room_id, period_year, period_month)` | 同一房间同月只能有一条读数 |
| `bills` | `(lease_id, bill_year, bill_month)` | 同一租约同月只能有一条账单 |

### 3.2 唯一约束脚本

```sql
-- 水电读数唯一约束
CREATE UNIQUE INDEX idx_utility_readings_unique ON utility_readings(room_id, period_year, period_month);

-- 账单唯一约束（需先清理重复数据）
-- CREATE UNIQUE INDEX idx_bills_unique ON bills(lease_id, bill_year, bill_month);
```

> ⚠️ 注意：添加唯一约束前需要先检查并清理现有重复数据

## 四、外键关联修复（中优先级）

### 4.1 通知表组织关联

当前 `notifications` 表有 `organization_id` 字段但缺少外键关联。

```sql
-- 添加外键（需要先确保数据一致性）
ALTER TABLE notifications
ADD CONSTRAINT fk_notifications_organization
FOREIGN KEY (organization_id) REFERENCES organizations(id) ON DELETE CASCADE;
```

## 五、字段建议（低优先级）

### 5.1 账单编号

建议在 `bills` 表添加业务编号字段：

```prisma
model Bill {
  id        String   @id @db.VarChar(26)
  bill_no   String   @unique @db.VarChar(32) // 新增：如 "BILL202603001"
  ...
}
```

### 5.2 租约状态

当前租约只有 `is_active` 布尔值，建议改为状态字段：

```prisma
model Lease {
  status String @default("active") @db.VarChar(20) // active, expired, terminated
  ...
}
```

### 5.3 冗余字段处理

`Bill` 表中 `water_amount`、`electricity_amount`、`other_amount` 与 `BillFeeItem` 存在冗余：

- **方案 A**：保留冗余字段作为快照，便于历史查询
- **方案 B**：移除冗余字段，通过 `BillFeeItem` 计算

**建议采用方案 A**，保持当前设计但添加注释说明。
