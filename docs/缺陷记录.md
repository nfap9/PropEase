## BUG-E2E-002: 测试文案与前端不匹配（⚠️ 待优化）

### 严重程度
P1

### 状态
待前端添加 data-testid

### 问题描述
测试代码中使用了"仪表盘"、"首页"、"欢迎使用公寓管理系统"等文案作为定位器，但前端文案可能已经变更。
- `e2e/dashboard.spec.ts` 期望找到"首页"或"仪表盘"，但实际显示的可能是其他文案
- `e2e/business.auth.setup.ts` 期望找到"首页"或"欢迎使用公寓管理系统"，但用户没有组织时显示"欢迎"

### 建议解决方案
1. **短期**：使用 OR 逻辑支持多种文案
   ```typescript
   await expect(
     page.getByRole('heading', { name: '首页' })
       .or(page.getByRole('heading', { name: '仪表盘' }))
       .or(page.getByText('欢迎使用'))
   ).toBeVisible();
   ```

2. **长期**：全面使用 `data-testid` 方式
   - 前端添加 `data-testid` 属性
   - 测试代码使用 `page.getByTestId(...)`
   - 参考 `docs/测试改造总结.md` 中的完整清单

3. **实施步骤**：
   - 阅段 1：高优先级核心流程先添加（登录/注册、公寓、租约）
   - 阶段 2：中优先级页面（房间、租客、账单、水电）
   - 阶段 3：低优先级页面（设置、通知、运营端）

### 影响范围
- 所有依赖文案定位的测试用例
- 测试覆盖率可能因文案变更而降低

### 问题描述

业务端 E2E 测试的登录态 setup 脚本执行失败。登录成功后，测试无法找到期望的页面元素，导致登录态文件无法创建，进而阻塞所有业务端测试用例的执行。

### 错误信息

```
Error: expect(locator).toBeVisible() failed
Locator: getByRole('heading', { name: '仪表盘' }).or(getByText('欢迎使用公寓管理系统'))
Expected: visible
Timeout: 5000ms
Error: element(s) not found
```

### 复现步骤

1. 运行测试：`pnpm exec playwright test --project=business-setup`
2. 观察测试结果

### 根本原因

1. **测试代码与前端文案不匹配**：
   - 测试代码 `e2e/business.auth.setup.ts:40-41` 期望找到"仪表盘"或"欢迎使用公寓管理系统"
   - 实际前端页面 `dashboard-content.tsx:112` 显示的标题是"首页"

2. **"欢迎使用公寓管理系统"不显示**：
   - 该提示仅在用户没有组织时显示 (`dashboard-content.tsx:87-98`)
   - 新注册用户会自动创建"个人"组织，不会看到此提示

### 预期结果

登录成功后应正确跳转到仪表盘页面，测试能够验证页面标题或欢迎语。

### 实际结果

登录成功后页面加载，但测试无法找到期望的文本元素，导致超时失败。

### 影响范围

- 业务端所有需要登录态的 E2E 测试无法运行
- 测试覆盖率严重降低

### 修复建议

**方案 1（推荐）：修改测试代码**
```typescript
// 修改 e2e/business.auth.setup.ts:40-41
await expect(
  page.getByRole('heading', { name: '首页' }).or(page.getByText('欢迎使用'))
).toBeVisible();
```

**方案 2：统一前端文案**
将 `dashboard-content.tsx` 中的"首页"改为"仪表盘"，保持与测试用例文档一致。

### 验证步骤

1. 应用修复方案
2. 重新运行：`pnpm exec playwright test --project=business-setup`
3. 确认测试通过
4. 验证 `e2e/.auth/business.json` 文件已创建
5. 运行业务端测试：`pnpm exec playwright test business`

- `e2e/business.auth.setup.ts`
- `web/src/app/dashboard/dashboard-content.tsx`

## BUG-E2E-003: 运营角色页标题断言失败（✅ 已修复 2026-03-06）

### 修复方式
- 修改 `e2e/admin.spec.ts:59-66` 移除对"运营角色"标题的断言，改为验证"新建角色"按钮可见性
- 修改 `e2e/admin.spec.ts:98-104` 移除对"运营角色"标题的断言，改为验证"新建角色"按钮可见性
- 原因：运营角色页为布局页，没有独立的"运营角色"标题，而是显示"请从左侧选择一个角色"

### 根本原因
运营角色页面采用了布局页面设计，侧栏包含导航，主内容区为角色列表，顶部没有独立的"运营角色"标题元素。

## BUG-E2E-004: 业务端导航 strict mode violation（✅ 已修复 2026-03-06）

### 修复方式
- 修改 `e2e/business.spec.ts:39` 添加 `exact: true` 参数：`page.getByRole('link', { name: '公寓管理', exact: true })`
- 修改 `e2e/business.spec.ts:718` 添加 `exact: true` 参数：`page.getByRole('link', { name: '公寓管理', exact: true })`

### 根本原因
页面顶部有"公寓管理系统"品牌链接（包含"公寓"文本），侧栏导航有"公寓管理"链接。Playwright 默认不精确匹配导致匹配到2个元素，触发 strict mode violation 错误。
