# 文档总览

本目录用于存放项目级说明文档，按“作用”而不是按“模块代码位置”组织。

## 文档分层

### 1. 产品与范围

- [原始需求](./原始需求.md)
  作用：保留项目最初的业务目标、范围与需求背景。
  维护建议：作为历史输入保留，不要求与现状逐项同步。

### 2. 契约与规范

- [API 契约说明](./api-contract/README.md)
  作用：说明请求/响应包装、契约来源与 OpenAPI 对照方式。
- [命名规范](./naming-conventions.md)
  作用：统一前后端、数据库与测试中的命名约定。

### 3. 测试用例

- [测试用例目录](./测试用例/README.md)
  作用：作为人工验收与 E2E 编写的业务检查表。
  维护建议：功能改动时优先同步这部分。

### 4. 设计稿

- [UI 设计目录](./ui-design/README.md)
  作用：保留页面视觉原型、交互草图与历史设计方案。
  维护建议：视作“设计参考”而非实现真相，必要时在 README 中标记历史状态。

## 当前维护原则

- 根 `README.md` 负责新同学的第一入口。
- `docs/` 负责跨模块的长期说明，不重复写启动命令细节。
- 模块内 `AGENTS.md` 负责面向开发者的局部工作约定。
- 测试用例文档负责描述“业务应该怎样工作”，不承担 API 设计文档职责。
- 设计稿负责表达意图和页面布局，不要求和当前实现完全一一对应。

## 建议阅读顺序

1. [仓库总览](../README.md)
2. [命名规范](./naming-conventions.md)
3. [API 契约说明](./api-contract/README.md)
4. [测试用例目录](./测试用例/README.md)
5. 对应模块的 `AGENTS.md`
