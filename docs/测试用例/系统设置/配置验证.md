# 配置验证测试用例

## 概述

配置管理使用 Zod 进行运行时验证，确保应用启动时配置正确。本文档描述配置验证的测试用例。

## 开发环境默认值

| 用例 | 输入 | 预期结果 |
|------|------|----------|
| 未设置 NODE_ENV | 不设置 | `isDev=true` |
| 未设置 APP_NAME | 不设置 | `appName='Apartment Ultra API'` |
| 未设置 SECRET_KEY | 不设置 | `secretKey='dev-secret-key-do-not-use-in-production'` |
| 未设置 CORS_ORIGINS | 不设置 | `corsOrigins=['http://localhost:3000']` |
| 自定义 APP_NAME | `APP_NAME=Custom` | `appName='Custom'` |
| DEBUG=true | `DEBUG=true` | `debug=true` |

## CORS_ORIGINS 解析

| 用例 | 输入 | 预期结果 |
|------|------|----------|
| JSON 数组 | `["http://a.com","http://b.com"]` | `['http://a.com', 'http://b.com']` |
| 通配符 | `*` | `true`（允许所有来源） |
| 单个 URL | `http://example.com` | `['http://example.com']` |
| 空值 | 不设置 | `['http://localhost:3000']` |

## 生产环境安全检查

| 用例 | 配置 | 预期结果 |
|------|------|----------|
| SECRET_KEY 使用默认值 | `SECRET_KEY=dev-secret-key-do-not-use-in-production` | 启动失败，提示"不能使用开发默认值" |
| SECRET_KEY 长度不足 | `SECRET_KEY=too-short` | 启动失败，提示"长度必须至少 32 个字符" |
| DATABASE_URL 使用本地默认 | 未设置 DATABASE_URL | 启动失败，提示"不能使用本地开发默认值" |
| CORS 设置为 "*" | `CORS_ORIGINS=*` | 启动失败，提示"不能设置为 '*'" |
| 所有安全配置正确 | 正确配置所有项 | 启动成功 |

### 生产环境正确配置示例

```bash
NODE_ENV=production
SECRET_KEY=this-is-a-very-long-secret-key-for-production-use-at-least-32-chars
DATABASE_URL=postgresql://user:password@prod-host:5432/database
CORS_ORIGINS=["https://your-domain.com"]
```

## 微信支付条件验证

| 用例 | 配置 | 预期结果 |
|------|------|----------|
| 微信支付禁用 | `WECHAT_PAY_ENABLED=false` | 其他微信配置可选，启动成功 |
| 微信支付启用但配置不完整 | 只设置 `WECHAT_PAY_ENABLED=true` | 启动失败，提示必须配置完整参数 |
| 微信支付启用且配置完整 | 设置所有必要配置 | 启动成功 |

### 微信支付必要配置

当 `WECHAT_PAY_ENABLED=true` 时，必须配置：
- `WECHAT_MCH_ID` - 商户号
- `WECHAT_APP_ID` - 应用 ID
- `WECHAT_CERT_SERIAL_NO` - 证书序列号
- `WECHAT_APIV3_KEY` - APIv3 密钥
- `WECHAT_PRIVATE_KEY` 或 `WECHAT_PRIVATE_KEY_PATH` - 私钥（二选一）

## 错误信息清晰度

验证失败时，错误信息应包含：
1. 具体的字段名称
2. 具体的错误原因
3. 配置建议

### 错误信息示例

```
[配置错误] 生产环境安全检查失败:
  - SECRET_KEY 不能使用开发默认值，请设置生产环境密钥（至少 32 个字符）
  - CORS_ORIGINS 不能设置为 "*"，请指定允许的域名

请检查环境变量配置后重试。
```
