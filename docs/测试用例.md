# Apartment Ultra 功能测试用例

本文档覆盖当前已实现功能的测试场景。**每条用例均包含**：用例编号、测试目的、前置条件、测试步骤、预期结果。需考虑不同情况（账号类型、用户/组织状态、运营端是否配置套餐与用量等）编写对应用例，便于手工测试与自动化参考。

**约定**：前置条件中未写则沿用该模块通用前置；涉及「免费/付费」时指组织订阅的套餐类型或未订阅；涉及「运营已配置」指运营后台已创建并启用套餐、且配置了组织数/公寓数/房间数/成员数等用量额度。

## 1. 认证模块（C 端用户）

**模块前置条件**：测试环境与 API 可用；短信验证码为 stub 时任意 6 位验证码可通过。负向用例需预先存在或不存在对应手机号/用户状态。

### 1.1 用户注册

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| AUTH-R-01 | 验证正常注册流程 | 手机号未注册；短信 stub 可用 | 打开注册页，输入有效手机号、姓名、密码（≥8 位且含字母与数字）、验证码，提交 | 注册成功，返回用户 id、phone、full_name、is_active、created_at；状态码 201 |
| AUTH-R-02 | 验证重复手机号拒绝 | 该手机号已注册 | 使用已注册手机号提交注册 | 返回 400，提示「手机号已注册」 |
| AUTH-R-03 | 验证手机号格式校验 | 无 | 手机号格式非法（非 1 开头的 11 位）提交 | 返回 422，参数校验失败，字段错误提示有效中国大陆手机号 |
| AUTH-R-04 | 验证姓名必填 | 无 | 姓名为空提交 | 返回 422，姓名不能为空 |
| AUTH-R-05 | 验证密码规则 | 无 | 密码少于 8 位或缺少字母/数字提交 | 返回 422，对应密码规则提示 |
| AUTH-R-06 | 验证验证码必填 | 无 | 验证码为空提交 | 返回 400，验证码不能为空 |

### 1.2 用户登录

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| AUTH-L-01 | 验证正常密码登录 | 用户已注册且账号启用（is_active=true） | 使用正确手机号与密码提交登录 | 返回 access_token、refresh_token、token_type: bearer |
| AUTH-L-02 | 验证错误凭证拒绝 | 无 | 使用错误密码或不存在手机号登录 | 返回 401，手机号或密码错误 |
| AUTH-L-03 | 验证验证码登录通路 | 短信 stub 可用 | 仅提供验证码（符合规则）提交登录 | 请求合法；验证码登录时 stub 不校验验证码内容 |
| AUTH-L-04 | 验证登录参数互斥 | 无 | 同时提供密码和验证码或两者都不提供 | 返回 422，参数校验失败 |
| AUTH-L-05 | 验证已停用用户无法登录 | 该用户已被运营停用（is_active=false） | 使用该用户正确手机号与密码提交登录 | 返回 401，不允许登录或账号已停用 |

### 1.3 刷新令牌

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| AUTH-F-01 | 验证有效 refresh 换新 token | 用户已登录且持有有效 refresh_token | 使用有效 refresh_token 调用 POST /auth/refresh | 返回新的 access_token、refresh_token |
| AUTH-F-02 | 验证无效/过期 refresh 拒绝 | 无 | 使用无效或过期的 refresh_token 调用 | 返回 401，Could not validate credentials |
| AUTH-F-03 | 验证停用用户 refresh 拒绝 | 用户已被停用 | 使用该用户有效 refresh_token 调用 | 返回 401 |

### 1.4 发送短信验证码

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| AUTH-S-01 | 验证发送验证码成功 | 无 | 提交有效 phone、purpose（login/register） | 204，开发环境下控制台打印验证码 |
| AUTH-S-02 | 验证参数校验 | 无 | 手机号格式非法或 purpose 非法 | 返回 422 |

### 1.5 当前用户信息

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| AUTH-M-01 | 验证已登录用户获取本人信息 | 已携带有效 access_token | 调用 GET /auth/me | 返回当前用户 id、phone、full_name、is_active、created_at |
| AUTH-M-02 | 验证未授权拒绝 | 未携带或无效 token | 调用 GET /auth/me | 返回 401 |

## 2. 组织模块

**模块前置条件**：C 端用户已登录；请求中已带有效 `x-org-id`（或当前有默认组织）。涉及套餐上限时，需运营已配置套餐及用量额度，且当前用户/组织用量满足对应场景。

### 2.1 组织列表

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| ORG-L-01 | 验证已登录用户获取组织列表 | 已登录 | 调用 GET /organizations（或带 x-org-id） | 返回用户所属组织列表（id、name、slug、plan、is_personal、is_active、role、created_at） |
| ORG-L-02 | 验证未登录拒绝 | 未登录 | 调用 GET /organizations | 返回 401 |
| ORG-L-03 | 验证运营停用组织后成员仍可拉列表但组织状态可见 | 用户为某组织成员，该组织已被运营停用 | 调用 GET /organizations | 列表中该组织 is_active 为 false 或状态可见 |

### 2.2 创建组织

## 3. 公寓与房间模块

**模块前置条件**：C 端用户已登录且已选当前操作组织（x-org-id）。涉及套餐公寓数/房间数上限时，需运营已配置套餐且当前组织用量满足对应场景。

### 3.1 公寓列表与创建

| 用例编号 | 测试目的 | 前置条件 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|----------|
| APT-L-01 | 验证已选组织可获取公寓列表 | 已登录且已选组织 | 调用 GET /apartments | 返回该组织下公寓列表，含 room_stats（total、available、occupied、maintenance） |
| APT-C-01 | 验证未达公寓数上限时可创建 | 组织公寓数未达套餐上限 | 提交 name，可选 address、description | 201，返回新公寓 |
| APT-C-01b | 验证达公寓数上限时创建拒绝 | 运营已配置套餐公寓数上限；当前组织公寓数已达上限 | 提交 name 创建公寓 | 返回 403，超过套餐公寓数限制 |
| APT-C-02 | 验证 name 必填 | 已登录且已选组织 | name 为空提交 | 返回 422 |

**说明：**

- 每条用例均包含：**用例编号**、**测试目的**、**前置条件**、**测试步骤**、**预期结果**。执行前请按前置条件准备环境（如账号类型、运营配置、数据状态）。
