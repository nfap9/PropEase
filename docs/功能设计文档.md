## 一、系统概述

### 1.1 产品定位

公寓管理系统（Apartment Ultra）是一款面向公寓运营者（"二房东"）的 SaaS 管理软件，帮助用户高效管理公寓、房间、租客、租约、水电和账单等业务。

### 1.2 用户角色

| 角色 | 说明 | 使用系统 |
|------|------|----------|
| 业务用户 | 公寓运营者及其团队 | 业务端（Web） |
| 运营管理员 | 平台运营人员 | 运营后台（Admin） |

### 1.3 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                        前端应用                              │
├─────────────────────────┬───────────────────────────────────┤
│      业务端 (Web)        │         运营后台 (Admin)          │
│  - Next.js 14            │    - Next.js 14                  │
│  - React 19              │    - React 19                    │
│  - Tailwind CSS          │    - Tailwind CSS                │
└─────────────────────────┴───────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                        API 服务                              │
│               Node.js + Express + TypeScript                 │
│                     /api/v1/*                                │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       数据存储                               │
│            PostgreSQL + Prisma ORM + Redis                  │
└─────────────────────────────────────────────────────────────┘
```

## 二、用户认证模块

### 2.1 功能概述

用户认证模块负责业务端用户的身份验证，支持密码登录和验证码登录两种方式。

### 2.2 功能清单

#### 2.2.1 用户注册

| 项目 | 说明 |
|------|------|
| **功能编号** | AUTH-001 |
| **功能名称** | 用户注册 |
| **入口** | `/register` |
| **前置条件** | 无 |

**输入字段**:

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| phone | string | 是 | 11位手机号格式 | 手机号 |
| password | string | 是 | 8-20位，包含字母和数字 | 密码 |
| confirmPassword | string | 是 | 与password一致 | 确认密码 |
| code | string | 是 | 6位数字 | 短信验证码 |

**业务规则**:
1. 手机号不能重复注册
2. 需先发送验证码验证手机号有效性
3. 开发环境验证码固定为 `123456`
4. 注册成功后自动创建个人组织

**API 端点**: `POST /api/v1/auth/register`

**测试用例**:
- AUTH-001-01: 正常注册流程
- AUTH-001-02: 重复手机号注册（返回错误）
- AUTH-001-03: 验证码错误
- AUTH-001-04: 密码强度不足
- AUTH-001-05: 两次密码不一致

---

#### 2.2.2 密码登录

| 项目 | 说明 |
|------|------|
| **功能编号** | AUTH-002 |
| **功能名称** | 密码登录 |
| **入口** | `/login` |
| **前置条件** | 已注册账号 |

**输入字段**:

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| phone | string | 是 | 11位手机号格式 | 手机号 |
| password | string | 是 | 非空 | 密码 |
| loginType | string | 是 | 固定值 "password" | 登录方式 |

**业务规则**:
1. 验证手机号和密码匹配
2. 账号被停用时拒绝登录
3. 登录成功返回 JWT Token（access_token + refresh_token）

**API 端点**: `POST /api/v1/auth/login`

**测试用例**:
- AUTH-002-01: 正确密码登录
- AUTH-002-02: 错误密码登录
- AUTH-002-03: 不存在的手机号
- AUTH-002-04: 账号已停用
- AUTH-002-05: 已登录用户访问登录页自动跳转

---

#### 2.2.3 验证码登录

| 项目 | 说明 |
|------|------|
| **功能编号** | AUTH-003 |
| **功能名称** | 验证码登录 |
| **入口** | `/login` |
| **前置条件** | 已注册账号 |

**输入字段**:

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| phone | string | 是 | 11位手机号格式 | 手机号 |
| code | string | 是 | 6位数字 | 验证码 |
| loginType | string | 是 | 固定值 "sms" | 登录方式 |

**业务规则**:
1. 验证码5分钟内有效
2. 验证码使用后立即失效
3. 开发环境固定验证码 `123456`

**API 端点**: `POST /api/v1/auth/login`

**测试用例**:
- AUTH-003-01: 正确验证码登录
- AUTH-003-02: 错误验证码
- AUTH-003-03: 过期验证码

---

#### 2.2.4 发送验证码

| 项目 | 说明 |
|------|------|
| **功能编号** | AUTH-004 |
| **功能名称** | 发送短信验证码 |
| **入口** | 登录/注册页面 |
| **前置条件** | 无 |

**输入字段**:

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|

**业务规则**:
1. 同一手机号60秒内只能发送一次
2. 验证码6位数字，5分钟有效
3. 开发环境固定返回 `123456`

**API 端点**: `POST /api/v1/auth/sms/send`

---

#### 2.2.5 刷新令牌

| 项目 | 说明 |
|------|------|
| **功能编号** | AUTH-005 |
| **功能名称** | 刷新访问令牌 |
| **入口** | 自动（Token过期时） |
| **前置条件** | 有有效的refresh_token |

**业务规则**:
1. access_token 有效期 2 小时
2. refresh_token 有效期 7 天
3. 用户停用时 token 失效

**API 端点**: `POST /api/v1/auth/refresh`

---

| **前置条件** | 已登录 |

**返回字段**:
- 用户ID、姓名、手机号

- 当前组织信息

**API 端点**: `GET /api/v1/auth/me`

## 三、组织管理模块

### 3.1 功能概述

组织是业务数据隔离的基本单位，用户可以创建和管理多个组织，组织内可邀请成员协作。

### 3.2 数据模型

```
Organization {
  id: string              // 主键（ULID）
  name: string            // 组织名称
  slug: string            // URL标识（唯一）
  type: string            // 类型：individual/partnership/company
  notes: string           // 备注
  settings: JSON          // 组织设置
  is_personal: boolean    // 是否个人组织
  is_active: boolean      // 是否激活
}
```

### 3.3 功能清单

#### 3.3.1 组织列表

| 项目 | 说明 |
|------|------|
| **功能编号** | ORG-001 |
| **功能名称** | 获取组织列表 |
| **入口** | 顶部导航栏组织切换 |
| **前置条件** | 已登录 |

**返回信息**:
- 用户所属的所有组织
- 每个组织的成员数量
- 当前选中的组织标识

**API 端点**: `GET /api/v1/organizations`

---

#### 3.3.2 创建组织

| 项目 | 说明 |
|------|------|
| **功能编号** | ORG-002 |
| **功能名称** | 创建组织 |
| **入口** | 组织切换下拉框 > 创建组织 |
| **前置条件** | 已登录，未超出组织配额 |

**输入字段**:

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| name | string | 是 | 2-50字符 | 组织名称 |
| type | string | 否 | individual/partnership/company | 组织类型 |
| notes | string | 否 | 最多500字符 | 备注 |

**业务规则**:
1. 组织名称不能重复
2. 创建者自动成为组织 owner
3. 受订阅套餐组织数量限制

**API 端点**: `POST /api/v1/organizations`

**测试用例**:
- ORG-002-01: 正常创建组织
- ORG-002-02: 组织名称为空
- ORG-002-03: 组织名称重复
- ORG-002-04: 超出配额限制

#### 3.3.4 删除组织

## 五、房间管理模块

### 5.1 功能概述

房间是租约的载体，管理房间的状态、租金和设施信息。

### 5.2 数据模型

```
Room {
  id: string              // 主键
  apartment_id: string    // 公寓ID
  room_number: string     // 房间号
  layout: string          // 户型
  status: string          // 状态：available/occupied/maintenance
  monthly_rent: decimal   // 月租金
  area: decimal           // 面积
  facilities: JSON        // 设施配置
  notes: string           // 备注
}
```

## 十五、系统约束与限制

### 15.1 数据限制

| 约束项 | 限制 |
|--------|------|
| 手机号格式 | 11位数字，1开头 |
| 密码强度 | 8-20位，包含字母和数字 |
| 验证码有效期 | 5分钟 |
| 验证码重发间隔 | 60秒 |
| JWT Access Token | 2小时有效 |
| JWT Refresh Token | 7天有效 |

### 15.2 配额限制

| 配额项 | 免费版 | 基础版 | 专业版 | 企业版 |
|--------|--------|--------|--------|--------|
| 组织数 | 1 | 3 | 10 | 无限 |
| 公寓数 | 1 | 5 | 20 | 无限 |
| 房间数 | 10 | 100 | 500 | 无限 |
| 成员数 | 1 | 5 | 20 | 50 |

### 15.3 业务规则

1. **删除保护**:
   - 有房间的公寓不能删除
   - 有活跃租约的房间不能删除
   - 有活跃租约的租客不能删除
   - 有账单的租约不能删除

2. **状态联动**:
   - 创建租约 → 房间状态变为已出租
   - 终止租约 → 房间状态变为空置

3. **账单生成**:
   - 同一租约同月不能重复生成账单
   - 未录入水电的房间不计算水电费用

4. **权限继承**:
   - 组织 owner 拥有所有权限
   - 权限可被自定义角色覆盖
