## 用例编号规范

```
{模块前缀}-{类型}-{序号}

类型：
- L: 列表 (List)
- C: 创建 (Create)
- G: 详情 (Get)
- E: 编辑 (Edit)
- D: 删除 (Delete)

- MB: 成员 (Member)
```

示例：`AUTH-R-01`（认证-注册-01）、`APT-C-01`（公寓-创建-01）

## 测试编写要点

### 不同情况覆盖
- **账号类型**：免费/付费套餐、已停用用户
- **运营配置**：未配置/已配置套餐、达上限/未达上限
- **角色权限**：owner/admin/member、超级管理员

### 前置条件
- 所有需「已登录」的接口需携带 `Authorization: Bearer <token>`
- 需组织的接口需携带 `x-org-id`
- 运营后台使用 Admin JWT（与 C 端分离）

### 负向用例必测
- 参数校验失败（422）
- 权限不足（403）
- 资源不存在（404）
- 套餐上限（403）
